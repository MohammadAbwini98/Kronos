# Dashboard Functionality Audit

Audited on 2026-05-09. The dashboard is a server-rendered single-page HTML app returned by `GET /` from `src/dashboard_server.py` and generated by `src/dashboard_ui.py`. It uses vanilla JavaScript, `<canvas>` charts, tab panels, direct `fetch` calls, and a Python `ThreadingHTTPServer`; there is no separate npm frontend, router, component framework, or package build step.

## Project Surface

| Area | Current Implementation | Notes |
|---|---|---|
| Frontend entry point | `dashboard_ui.dashboard_html()` | Inline HTML, CSS, and JavaScript string. |
| Backend entry point | `DashboardHandler` in `src/dashboard_server.py` | Serves `/`, JSON API endpoints, and safe in-repo files through `/file`. |
| Routing system | Single page plus API routes | Tabs are client-side panels, not URL routes. |
| State management | Module-level JavaScript variables | `latest`, `latestSignals`, `latestModelPerformance`, `signalFilters`, `signalPage`, `activeTab`, timers, and selected run id. |
| API client | Browser `fetch` calls | `refreshStatus`, `refreshSignals`, `postJson`, and action-specific helpers. |
| Design system | Inline CSS tokens | Uses CSS variables for colors, radius, shadows, panels, chips, buttons, tables, and charts. |
| Tests | Python `unittest`/`pytest` | Dashboard contract tests exist in `tests/test_dashboard_ui_contract.py`, `tests/test_dashboard_server_security.py`, and `tests/test_dashboard_server_status_warnings.py`. |
| Build/lint commands | None declared | No `package.json`, `pyproject.toml`, `setup.cfg`, `tox.ini`, `Makefile`, `.flake8`, or `ruff.toml` was found. |

## Redesign Plan

1. Keep the existing HTML structure, element IDs, data attributes, event handlers, endpoint paths, and payload shapes intact.
2. Rework the inline CSS into a cohesive Apple-inspired token system: neutral adaptive colors, glass panels, soft shadows, rounded controls, consistent focus/hover/disabled states, and light/dark theme support through `prefers-color-scheme`.
3. Refine shell layout, cards, controls, tabs, tables, charts, loader, toast, worker cards, and validation banners without removing mapped controls.
4. Add or strengthen tests that lock key route/control mappings and visual-system contracts.
5. Validate via Python tests, endpoint smoke checks, and browser/static interaction checks where available.
