# PL-001: Implement and Verify New Suggestions

## Summary

Implement and verify every point listed in `suggestions/NEW_SUGGESTIONS_IMPLEMENTED.md` after reviewing the current project codebase. The codebase already contains most of the requested behavior, so this plan focuses on confirming correctness, closing documentation/config gaps, and adding targeted tests around the new safety controls.

The implementation must preserve the project boundary: this bridge remains data-only and must not place trades, open positions, close positions, manage working orders, or call trading endpoints.

## Current Codebase Findings

- Heartbeat freshness handling is already present in `dashboard_db.postgres_dashboard_snapshot`: worker states receive `stale_seconds`, `stale_alert`, and `OK` heartbeats older than 180 seconds become `STALE`.
- Dashboard warnings already surface stale workers through `/api/status`, and the UI worker cards already display heartbeat age.
- Auto-finetune command placeholder validation is already present in `main_auto_finetune_worker.py`, requiring both `{dataset}` and `{model_dir}` before command execution.
- Auto-finetune promotion gating is already present: promotion requires model readiness, minimum matched candles, minimum direction accuracy, and improvement over the prior promoted accuracy when available.
- Production model selection already avoids unapproved auto-finetuned models through `main_run_kronos_predict._auto_finetuned_model_dir`.
- Worker supervisor controls are already present in `start_dashboard.ps1`: `WORKER_RESTART_MAX_ATTEMPTS`, `WORKER_MONITOR_INTERVAL_SECONDS`, and `ENABLE_MAINTENANCE_WORKER`.
- `.env.example` does not yet list the newer auto-finetune, promotion, maintenance, logging, and supervisor environment variables, so operators do not have one clear configuration reference.
- The repository does not currently have a test suite directory, so verification should introduce focused tests rather than relying only on manual dashboard inspection.

## Implementation Changes

### 1. Heartbeat Freshness Guard

- Keep the 180-second worker heartbeat threshold in `dashboard_db.postgres_dashboard_snapshot`.
- Ensure default worker states remain present for `prediction_scheduler`, `validation_worker`, `websocket_stream`, `auto_finetune_worker`, and `maintenance_worker`.
- Preserve the response fields `status`, `details`, `updated_at`, `stale_seconds`, and `stale_alert` for each worker.
- Keep stale `OK` workers converted to `STALE`, while preserving explicit `ERROR` and `MISSING` statuses.
- Ensure `/api/status` warnings include stale worker names and heartbeat age.
- Ensure dashboard worker cards display heartbeat age and a warning chip for `STALE`.

### 2. Stronger Auto-Finetune Command Safety

- Keep command execution blocked when `KRONOS_FINETUNE_COMMAND` is empty.
- Keep command execution blocked when the command template is missing either `{dataset}` or `{model_dir}`.
- Preserve status output fields for skipped runs: `action`, `reason`, and `hint`.
- Document the required command template format in README and `.env.example`.
- Keep optional placeholders `{symbol}` and `{resolution}` supported by `.format(...)`.

### 3. Promotion Must Beat Prior Promoted Baseline

- Preserve `promoted_direction_accuracy_pct` in `output/auto_finetune_status.json`.
- Keep promotion approval gated by:
  - auto-finetuned model artifacts are ready,
  - matched candles meet `AUTO_FINETUNE_PROMOTION_MIN_MATCHED_CANDLES`,
  - direction accuracy meets `AUTO_FINETUNE_PROMOTION_MIN_DIRECTION_ACCURACY`,
  - direction accuracy is strictly greater than the previous promoted baseline when one exists.
- Keep unapproved models out of production prediction selection.
- Ensure status reasons remain explicit: `model_artifacts_missing`, `matched_candles_below_threshold`, `direction_accuracy_unavailable`, `direction_accuracy_below_threshold`, `direction_accuracy_not_improved`, or `promotion_criteria_met`.

### 4. Supervisor Configurability

- Keep `start_dashboard.ps1` reading `WORKER_RESTART_MAX_ATTEMPTS` with default `20`.
- Keep `start_dashboard.ps1` reading `WORKER_MONITOR_INTERVAL_SECONDS` with default `5`.
- Keep `ENABLE_MAINTENANCE_WORKER` controlling whether `main_maintenance_worker.py` is launched.
- Add missing environment variable examples to `.env.example` for supervisor, auto-finetune, promotion, maintenance, and logging settings.
- Add README notes explaining the startup preflight, managed workers, restart limit, and maintenance toggle.

## Test Plan

Add focused tests under a new `tests/` directory.

- Test `_seconds_since` with `None`, timezone-aware timestamps, naive timestamps, ISO strings, and invalid values.
- Test worker stale status derivation by mocking database heartbeat rows where an `OK` heartbeat is older than 180 seconds.
- Test `/api/status` warning generation for stale websocket data, stale workers, missing required workers, and worker errors.
- Test `_promotion_decision` for every branch: missing model artifacts, insufficient matched candles, unavailable accuracy, below threshold, not improved, and approved.
- Test `_auto_finetuned_model_dir` returns no model when `promotion_status` is missing, pending, rejected, or model artifacts are incomplete.
- Test invalid auto-finetune command templates produce `invalid_finetune_command_template` and do not invoke subprocess execution.
- Test `start_dashboard.ps1` behavior manually with `ENABLE_MAINTENANCE_WORKER=false`, low restart limits, and custom monitor interval.
