# CN-001 - Forecast Outcome Improvement Roadmap

## Purpose

Create a numbered change-record map for improving forecast outcome analysis, data reading, and visualization in the Capital.com to Kronos bridge.

## Change-Record Convention

- Folder: `CR's`
- File format: `CN-<Number>.md`
- Number range: `0-100`
- Current sequence starts at `CN-001.md`
- Each implementation change should add the next `CN-###.md` file.
- Each note should include:
  - Summary
  - Files changed
  - Test or validation performed
  - Follow-up notes

## Seven-Point Roadmap

### 1. Forecast Review Visualization

Add a script that loads forecast, actual, metadata, and quality report files, then generates charts for:

- Forecast close vs actual close
- Forecast error over time
- Absolute error over time
- Direction hit/miss markers
- Volume context

Expected output:

```text
output/forecast_review_{epic}_{resolution}_{timestamp}.html
```

### 2. HTML Forecast Review Report

Generate a self-contained HTML report with:

- Metadata summary
- Forecast quality metrics
- Forecast vs actual charts
- Missing actual candles
- Tradability notes based on movement/cost thresholds

### 3. Actual Candle Matching Improvement

Improve actual candle collection by fetching a small buffer around the forecast window, then trimming locally by timestamp.

Goal:

- Reduce missing actual candles caused by API range inclusivity or timestamp alignment.
- Keep missing candle reporting explicit.

### 4. Forecast Runs Index

Maintain:

```text
output/forecast_runs_index.csv
```

Each row should include:

- Epic
- Resolution
- Price side
- Model
- Generated timestamp
- Forecast horizon
- Quality status
- MAE, RMSE, MAPE
- Direction accuracy
- Paths to input, forecast, metadata, actual, and quality report files

### 5. Experiment Setting Comparison

Support side-by-side evaluation of:

- `MINUTE_5` vs `MINUTE_15`
- `pred_len=3`, `6`, `12`
- `lookback=128`, `256`, `512`
- `feature-set=ohlc` vs `ohlcv`
- `price-side=bid`, `ask`, `mid`

Goal:

- Identify settings with better error metrics and direction accuracy.

### 6. Baseline Model Comparison

Add simple non-ML baselines:

- Naive close forecast
- Drift forecast
- Moving average forecast
- Last candle direction baseline

Compare Kronos against baselines using the same quality metrics.

### 7. Trading-Usefulness Analytics

Add analysis-only signal usefulness metrics:

- Expected move after spread/slippage threshold
- False positive rate
- Directional precision for UP/DOWN
- Average hypothetical win/loss if used as a signal
- Max adverse excursion
- HOLD classification after costs

Safety:

- Do not place trades.
- Do not create BUY/SELL execution logic.
- Do not call order, position, or working-order endpoints.
