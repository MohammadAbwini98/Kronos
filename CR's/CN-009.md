# CN-009 - Full Dashboard Enhancement Plan Implementation

## Summary

Implemented the 10-point dashboard enhancement plan as a single dashboard upgrade.

## Implemented Points

1. Actual plus forecast close chart.
2. Historical plus forecast candlestick visualization.
3. Prediction summary cards.
4. Prediction controls for market, resolution, forecast length, lookback, feature set, and OHLC repair.
5. Dashboard tabs for overview, forecast chart, candles, validation, baselines, risk, history, files, logs, and embedded report.
6. Actual-vs-forecast workflow buttons for fetching actuals and validating actuals.
7. Baseline comparison button for naive, moving average, drift, and last-direction baselines.
8. Forecast confidence/risk panel using validation and trading-usefulness fields.
9. Auto-refresh controls and an auto-predict-newest-candle toggle placeholder.
10. Run history table from timestamped forecast metadata.

## Files Changed

- `src/dashboard_server.py`

## Safety

- Dashboard remains data-only.
- No trading endpoints.
- No BUY/SELL execution logic.

## Validation

- `python -m compileall src/dashboard_server.py` passed.
- Restarted dashboard at `http://127.0.0.1:8765`.
- Verified dashboard HTML contains:
  - `Forecast Chart`
  - `Historical + Forecast Candles`
  - `Auto predict newest candle`
  - `Run Baselines`
- `GET /api/status` returned:
  - metadata
  - validation
  - forecast rows
  - actual/history rows
  - run history
- `POST /api/predict` returned `returncode=0` and generated an embedded HTML report URL.
- `POST /api/baselines` returned `returncode=0` and generated all four baseline forecasts.
- `POST /api/fetch-actual` was tested while the latest forecast window was still open; it returned a safe error explaining the forecast window had not completed.
- `POST /api/validate-actual` was tested without actual CSV for the latest forecast; it returned a safe missing-actual error.
