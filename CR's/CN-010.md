# CN-010 - Prediction WIN/LOSS Database

## Summary

Added a local SQLite prediction ledger so each Kronos forecast candle is persisted and later validated against the matching actual Capital.com candle.

## Changed Files

- `src/prediction_store.py`
- `src/main_prediction_db_status.py`
- `src/main_run_kronos_predict.py`
- `src/main_validate_forecast_quality.py`
- `src/dashboard_server.py`
- `README.md`

## Behavior

- Forecast generation saves one prediction run and one prediction record per forecast candle.
- Records are stored in `data/predictions.sqlite3` by default.
- Records start as `PENDING`.
- Forecast quality validation updates records to `WIN` or `LOSS` once actual candles exist.
- Dashboard status now includes local DB totals, pending records, win rate, and recent run rows.

## WIN/LOSS Rule

- First candle: predicted direction is compared against actual direction from the last input close.
- Later candles: predicted direction is compared candle-by-candle against the actual close path for the same timestamp and resolution.
- Flat moves use the configured flat threshold.

## Safety

This is data-only analytics. No trading endpoint, order endpoint, position endpoint, BUY/SELL execution logic, or live execution flow was added.
